# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

The public specification of weakmail (`spec.html`) and a no-build static web app of interactive
visualizations of its encoder and receiver, one page per step, with a shared transport clock.
Every algorithm in `src/wm/` is a JavaScript port of the Python reference implementation
**weakmail** (https://github.com/bodiya/weakmail, usually checked out next to this repo as
`../weakmail`). Faithfulness to weakmail is the rule: port from the Python, cite the module in a
comment, and check the port value by value. Never change what goes on the air here: the on-air
format is defined by weakmail's `docs/SPEC.md`. License GPL-3.0-or-later.

The site exists partly to publish the mode before on-air use (47 CFR §97.309(a)(4)). Keep the
specification complete and accurate; never describe anything as encrypted or hidden.

## Run and test

```bash
npm start                        # python3 -m http.server 8765
npm test                         # vectors_test + afsk_test + rx_test (about 45 s)
node tools/cdp_check.mjs         # must end "no console errors or exceptions"
node tools/cdp_check.mjs --mobile   # exits non-zero on layout or tap-target problems
node tools/cdp_shot.mjs <page> <out.png> ["<js run first>"] [--viewport=390x844] [--full]
python3 tools/build_spec.py ../weakmail     # rebuild spec.html (markdown, numpy, scipy)
python3 tools/make_fixtures.py ../weakmail  # rebuild receiver and AFSK fixtures
```

The CDP tools use `$CHROME`, else google-chrome, chromium, or the Playwright Chromium in
`/opt/pw-browsers`. After a UI change run both CDP sweeps and look at a screenshot at both sizes;
after a change in `src/wm/` run `npm test`. Expected: 313 vector checks, 57 AFSK checks, 114
receiver checks, all passing.

## Layout

```
index.html            shell: nav, transport bar, #stage
spec.html             GENERATED by tools/build_spec.py; edit tools/spec_parts/ or weakmail's SPEC.md
src/ui/               app.js (state: msg, tx, scenario, rx; routing; worker), clock, controls, draw, styles
src/wm/               the port: params, sha, ed25519, frame, ldpc, coded, mfsk, fft, stats, channel,
                      track, detect, modem, afsk1200, worker
src/vis/              one module per page: home, encode, code, signal, carrier, preamble, soft,
                      decode, frame, protocol, downlink; common.js holds shared panels
data/vectors/         weakmail's published test vectors, copied unchanged (served)
tools/                tests, CDP drivers, fixture and spec builders, fixtures/
```

## Conventions

- Headers: `Copyright (c) 2026 Brian Bodiya (KC1WIH)` and `SPDX-License-Identifier:
  GPL-3.0-or-later. See LICENSE.` Ports say which weakmail module they port.
- Plain ES modules, no dependencies, no bundler. Every runtime URL resolves against
  `import.meta.url`.
- Page module shape as in ft8-73: `export default { mount(root, app), unmount() }`, with `setTab`
  and `resize` assigned in mount and nulled in unmount; views live in the hash (`#page/view`).
- Shared state on `app`: `msg` (what E · Encode edits), `tx` (its encoding, null if it does not
  encode), `scenario` (the simulated channel), `rx` (the worker's trace), `rxState`.
  `app.ensureRx()` runs the receiver on the current message and scenario; pages gate on
  `rxGate()` from `src/vis/common.js`. Try-this experiments use `app.tryScenario(patch)`, which
  starts from the class's default scenario.
- LLR convention as the reference: LLR > 0 means bit 0. Bits are Uint8Array 0/1, MSB first.
- Records are `{ re, im }` Float32Array pairs at 24 kS/s, as the reference's complex64.
- Clock subscribers draw only overlays and quantize the clock; backgrounds are redrawn on data
  or control changes (the ft8-73 performance rules apply).
- UI text: no em-dashes; short blurbs; numbers in tables.

## Simulated, not recorded

weakmail has not been on the air yet, so the receiver pages run on captures simulated from the
encoded frame (`src/wm/channel.js`: ideal HT model, offset, drift, AWGN with a seeded generator).
Say so wherever a page could be mistaken for a recording.
